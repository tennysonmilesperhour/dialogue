# Product and engineering audit, September 6, 2026

## Scope and result

This audit covers the iOS app, all four extensions, shared persistence and scoring,
the marketing site, signup endpoint, database permissions, and release checks.
The changes improve the existing local-first product. They do not establish
physical-device reliability or measured retention lift.

## Findings addressed

| Priority | Finding | Change |
| --- | --- | --- |
| High | App and extensions overwrite entire stale snapshots in UserDefaults. | A shared file lock serializes read-modify-write transactions; atomic replacement preserves the previous file on write failure. Legacy data migrates on first access. |
| High | Returning to the app shields an active visit again. | Shield selection excludes active app IDs; pause opens all watched apps. |
| High | Failed monitoring leaves a user at a gate with no useful recovery. | Monitoring failure pauses gates; storage failures preserve existing bytes and open gates. |
| High | Browser insert API bypasses validation and reveals existing waitlist addresses. | Server endpoint verifies Turnstile hostname and action, limits payloads, normalizes email, uses bounded network requests, and gives identical new/duplicate responses. Migration removes direct public table access. |
| High | Private intentions remain in notifications after data deletion. | Notifications use generic text; deletion removes pending and delivered notifications and stops monitors. |
| Medium | Stale reflection IDs hide later entries; Later prompts again on foreground. | Derive the queue from valid closed entries, defer for the current app run, and offer reflection actions in ledger history. |
| Medium | Main-app Never mind does not count as a walk-away. | Record the dismissal transactionally. |
| Medium | Removing a watched app or pausing leaves monitoring active. | Close the affected visits approximately and stop their monitors. |
| Medium | Empty scores and adaptive gates lack an explanation. | Add first-entry guidance, sample counts, score formula, tier context, pause and authorization recovery. |
| Medium | Review durations imply precise app usage. | Label elapsed visit estimates explicitly and exclude active visits from unfinished-reflection totals. |
| Medium | Website mock buttons do nothing and promises exceed the binary. | Add an interactive intention/reflection preview, responsive editorial layout, earlier CTA, and accurate free/local-only release copy. |
| Medium | Failed signup can remain disabled indefinitely. | Recover from exceptions and timeouts, retain the address on failure, announce status, and reset verification for retry. |
| Medium | No public-service configuration boundary or security response headers. | Server-only environment configuration, honest paused state, anti-framing and content-type headers, restricted browser capabilities. |
| Low | Unused database client increases web dependencies. | Remove the Supabase JavaScript client; the server uses its narrow REST insert endpoint. |

## Validation

- 26 DialogueKit tests pass, including 100 concurrent writers and corruption preservation.
- Seven web tests pass, including the actual PostgreSQL permission migration.
- TypeScript checking and the Next.js production build pass.
- npm audit reports zero vulnerabilities.
- Device-SDK Release and simulator builds pass with signing disabled.
- Native runtime validation remains unresolved: the unsigned simulator run
  rendered the storage-recovery alert and logged missing App Group entitlement.
  An ad hoc signing attempt encountered synced-folder metadata, then simulator
  launch denial. No successful Screen Time or native end-to-end run is claimed.
- Browser checks cover all three pages at 320, 390, 768, and 1440 pixels,
  with no horizontal overflow or WCAG A/AA violations detected by axe.
- The preview completes both reflection and walk-away paths without page errors.
- The configured form preserves the email after failure, retries successfully,
  and focuses the success message. Verification and API responses were mocked;
  this is not a live-provider acceptance test.
- Packaged app and four extensions pass bundle ID, version, privacy manifest,
  icon, device-family, export-compliance, and entitlement-file checks.
- Product copy lint and whitespace checks pass.

Screenshots are recorded with the final audit handoff.
The regression suite covers concurrent ledger writers, corruption preservation,
one-time pending gates, stale reflection queues, and shield selection. API tests
cover normalization, duplicate privacy, malformed/oversized/cross-origin requests,
challenge failure, absent configuration, and service failures. The migration is
executed against local PostgreSQL through PGlite with actual role changes.

## Release gates that remain

1. Run D012 on a physical iPhone, including iOS 17 fallback notification handoff,
   delayed monitor callbacks, foreground transitions, denied notifications,
   permission revocation, pause/resume, and deletion during a callback. The
   simulator cannot validate Screen Time interception.
2. Confirm Family Controls distribution approval and produce a signed archive.
3. Restore or replace the waitlist database. Apply both migrations in order,
   configure `web/.env.example`, restrict the Turnstile widget to deployment
   hostnames, and verify one real signup plus denied direct browser access.
   The existing deployment must be coordinated with the migration because the
   old browser form intentionally loses insert permission. No live schema or
   production deployment was changed during this audit.
4. Provide a private support/deletion channel. GitHub Issues is public; it cannot
   safely receive waitlist addresses or private ledger details. Do not promise
   same-day deletion until an operational channel and process exist.
5. Test VoiceOver and larger Dynamic Type on the smallest supported iPhone.
   Existing native multi-column layouts need device assessment beyond compilation.
6. Measure beta outcomes before claiming effectiveness: debrief completion,
   weekly return, and week-six retention. Keep measurement voluntary and local
   or based on explicitly shared beta feedback; no analytics SDK was added.

## Retention hypotheses to test

- Explaining the first score and resurfacing unfinished entries should reduce
  confusion before the second reflection. Compare first-visit to first-reflection
  completion and return within seven days.
- A preview that demonstrates the exit reflection should attract users who value
  the core product. Compare preview completion to beta requests when signups resume.
- Generic notifications protect privacy but may change response rate. Ask beta
  participants whether reminders are recognizable without revealing intentions.
- The 1,000-entry on-device retention limit is now disclosed in Settings. Before
  public release, evaluate a local export/archive workflow with beta users.
